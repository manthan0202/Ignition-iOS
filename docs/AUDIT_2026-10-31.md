# Ignition audit — build `HOME_Scenery_Pins_Synced_2026-10-31`

**Read this first.** This audit was done by reading the source on Linux. There is no Swift toolchain, Xcode, or iPhone
in that environment. So: **nothing here is verified as compiling or as working on a device.** "Built" below means
"the code for it exists and reads correctly"; it does not mean "works". Every claim that needs a phone is in
`DEVICE_ACCEPTANCE_RUNBOOK.md`.

Line numbers refer to the tree as delivered (before the patch in `ignition_audit_fixes.patch`).

## 1. Project wiring (checked mechanically, not by Xcode)
- `project.pbxproj` parses. 7 targets; every target contains every project type it references (script check, 0 unresolved).
- Extensions are embedded into PlugIns. Versions are set (`MARKETING_VERSION`, `CURRENT_PROJECT_VERSION`), so no empty `CFBundleVersion`.
- `IGNITION_PREVIEW` is set for IgnitionPreview in both Debug and Release; the Preview `ProtectionService` is a safe stub.
- The Full and Preview Live Activity UIs are identical apart from the `@main` bundle. A Preview result transfers to Full.
- **Still `com.example.*`** for all bundle IDs and the App Group (`group.com.example.ignition`). You must replace them with IDs your team can register.
- **Preview and Full do not share data.** Preview has no App Group, so it stores in Application Support; Full stores in the App Group container. Moving between them looks like data loss. A Full build whose App Group is provisioned *later* will also start empty.
- Both apps register the `ignition://` URL scheme. With both installed, a Live Activity tap may open either.
- `Scripts/check_home_patch.py` fails on the delivered tree (11/13 gates): it greps strings from an older Home implementation. It is obsolete, not a regression, and `verify_revision.sh` does not call it. Delete or rewrite it so nobody trusts it.
- `Scripts/verify_xcode_references.py` needs macOS (`plutil`); could not run.

## 3. Findings not patched (need your decision or a device)
### 3.1 The lock-in dot is hidden for the first 11–17 minutes
`LivingDay.swift` 151–163 draws footprints *under* the Now capsule (zIndex 4 at line 242; capsule is 41 pt tall, line 235).
A footprint is at `nowY + elapsed × pointsPerHour`. Hidden while that offset < ~25 pt:
Near (135 pt/h) ≈ 11 min · Hours (88) ≈ 17 min · Day (48) ≈ 31 min. A session you end after 2 minutes shows no dot at all until then.
Not patched because every fix changes the approved look: (a) draw above the capsule, (b) offset the dot beside the path, or
(c) ring the Now marker while a session is active. Tell me which and I will do it.
### 3.2 Accidental block moves, no undo
`PlanView.swift` 1263: block move is a `highPriorityGesture(DragGesture(minimumDistance: 8))` on a 18–31 pt title strip, with no long-press pickup.
Swiping to scroll that starts on a block title can move it, and there is no Undo (§2 row 17). Event blocks use `.draggable` and `.contextMenu` on the same view (lines 682, 1614); both start on long-press and may conflict. Test G.
### 3.3 Other
- Live Activity: if no matching activity exists, `endAll()` suspends before `request`; the serialized refresh prevents most overlap but `completeBlockTask` (AppModel ~118) bypasses it.
- Parser: "at 7:30" with no AM/PM leaves ":30" in the title.
- `Info.plist` has no `NSSupportsLiveActivitiesFrequentUpdates`; not needed for this design.
- `ShieldAction` direct return is behind `IGNITION_ENABLE_DIRECT_SHIELD_RETURN`; `openParentalControlsApp` exists in Apple's docs but I could not confirm the `iOS 26.5` availability gate. Leave it off unless you build against an SDK that has it.
